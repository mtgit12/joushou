| 項目 | 内容 |

このドキュメントは、本プロジェクトで使う用語の意味と、コードで使う英語名を定めます。ドキュメント・画面の文言・コード（フロントエンド、バックエンド、データベース、API）で同じものを同じ言葉で呼ぶための、唯一の対応表です（ユビキタス言語）。

---

## 1. このドキュメントの使い方

### 1.1 ルール

- ドメインの用語は、フロントエンドとバックエンドで**同じ英語名**を使う。
- 新しい用語が必要になったら、コードを書く前にこのドキュメントへ追加する。
- 用語の意味や英語名を変えるときは、このドキュメントを先に更新し、関連するドキュメントとコードをあわせて直す。
- 画面の文言は「日本語」の列の言葉を使う。「使わない言葉」（5章）は、画面にもドキュメントにも使わない。

### 1.2 英語名からの名前の作り方

この表では、英語名を単数形の PascalCase で書きます。それ以外の場所では、各開発規約の命名規則に従って次のように変換します。

| 使う場所 | 形 | 例（城：`Castle`） | 例（訪問記録：`Visit`） |
|---|---|---|---|
| クラス、型、集約のディレクトリ | PascalCase の単数形 | `Castle` | `Visit` |
| 変数、プロパティ、zod スキーマ | camelCase | `castle`、`castleId` | `visit`、`visitSchema` |
| テーブル | snake_case の複数形 | `castles` | `visits` |
| カラム（外部キー） | snake_case＋`_id` | `castle_id` | `visit_id` |
| URL のパス | kebab-case の複数形 | `/castles` | `/visits` |

区分値（3章）の値は、コードでは小文字の文字列（API、URL、DB）として扱い、PHP の enum のケースは PascalCase（例：`ContributionStatus::Pending`）とします。

| 取り下げ | `cancel` | 審査待ちの情報提供を、提供者が自分で取り消すこと | 退会（`withdraw`）と区別するため `cancel` とする |
| 公開データ | ― | 一般の利用者に表示される、城・武将などのデータ | 承認されるまで情報提供は反映されない |

### 2.8 年

### 3.3 家族関係の種類（`KinshipType`）

家族関係は、人物（武将・女性）同士の間に「A から見て B は何か」の形で登録します。片方を登録すると、相手側の関係も自動で登録します。父親か母親か、妻か夫かは種類では区別せず、人物の性別（武将は性別の項目、女性は常に女性）で決めて表示します。

| 値 | 日本語 | 相手側に反映される種類 | 表示 | 制約 |
|---|---|---|---|---|
| `parent` | 親 | `child` | B が男性なら父親、女性なら母親 | |
| `adoptive_parent` | 養親 | `adopted_child` | B が男性なら養父、女性なら養母 | |
| `child` | 子 | `parent` | 子 | |
| `adopted_child` | 養子・養女 | `adoptive_parent` | B が男性なら養子、女性なら養女 | |
| `sibling` | 兄弟姉妹 | `sibling` | 兄弟姉妹 | |
| `spouse` | 配偶者 | `spouse` | B が女性なら妻、男性なら夫 | A と B の性別が異なること。妻の区分（3.10）を持つ |

実の親として登録できるのは、男性・女性それぞれ1人までとします。

## 4. マスタデータ

各値のコードの一覧は `design/data-model.md` で定めます。ここでは名前とコードの形式を定めます。

| 日本語 | 英語名 | コードの形式 | 例 |
|---|---|---|---|
| 都道府県 | `Prefecture` | JIS X 0401 の2桁の数字 | `20`（長野県）、`23`（愛知県） |
| 旧国名 | `Province` | ヘボン式ローマ字の小文字 | `owari`（尾張）、`shinano`（信濃） |
| 元号 | `Era` | ヘボン式ローマ字の小文字 | `eiroku`（永禄） |
| 城郭構造 | `CastleStructure` | ヘボン式ローマ字の小文字 | `yamajiro`（山城）、`hirayamajiro`（平山城）、`hirajiro`（平城）、`umijiro`（海城） |
| 所属勢力 | `Faction` | 家名のヘボン式ローマ字の小文字 | `oda`（織田家）、`takeda`（武田家） |
| 官位 | `CourtRank` | ヘボン式ローマ字の小文字。単語の区切りは `_` | `kazusa_no_suke`（上総介）、`ju_sanmi`（従三位）、`naidaijin`（内大臣） |

所属勢力と官位は初期データとして投入し、その後は管理画面（A-18、A-19）から追加・編集します（`requirements.md` US-26）。コードは追加後に変更できず、削除もできません。それ以外のマスタデータは、管理画面からは変更しません。

## 5. 使わない言葉

表記ゆれを防ぐため、次の言葉は画面・ドキュメント・コードで使いません。

| 使わない言葉 | 使う言葉 | 理由 |
|---|---|---|
| 投稿、申請、報告 | 情報提供 | 用語を1つに揃えるため |
| 採用、不採用 | 承認、却下 | 審査の結果を表す言葉を揃えるため |
| お気に入り武将、推しメン | 推し武将 | |
| 大名、戦国大名 | 武将 | 大名は武将の一部。勢力を指す場合は「所属勢力」 |
| チェックイン、登城記録 | 訪問記録 | |
| ユーザー（会員を指す場合） | 会員 | 「ユーザー」は Better Auth の認証用アカウント（`User`）と紛らわしい。ただし「未ログインユーザー」「退会ユーザー」「ユーザー名」「ユーザー管理」は定着した言い方として使ってよい |
| 削除（退会の意味で） | 退会 | 管理者による論理削除と区別するため |
| 御朱印 | 御城印 | 御朱印は寺社のもの |
| 兄弟（姉妹を含む意味で） | 兄弟姉妹 | 女性を登録するため、姉妹を含むことを明示する |
| 親族、家系、血縁 | 家族関係 | 用語を1つに揃えるため |
| `master`、`liege`（主君の意味で） | `lord` | `master` はマスタデータ（`master data`）と紛らわしいため |
| `lord`（城主の意味で） | `castellan` | `lord` は主君で使うため |
| 継室（区分として） | 正室 | 継室は正室に含める。継室であることは略歴に書く |
| `VisitRecord`、`VisitHistory`、`visit_records` | `Visit`、`visits` | 訪問記録の英語名を `Visit` に揃えるため |
| `next100` | `zoku100` | 正式名称の「続」に揃えるため |
| `withdraw`（取り下げの意味で） | `cancel` | 退会の `withdraw` と区別するため |
