| 項目 | 内容 |

このドキュメントは、第一フェーズで「何を作るか」を定めます。目的・スコープ・原則は `constitution.md` を参照してください。

---

## 1. このドキュメントの読み方

### 1.1 要件 ID

| 接頭辞 | 意味 |
|---|---|
| `US-xx` | ユーザーストーリー（機能要件） |
| `NFR-xx` | 非機能要件 |
| `AC-xx-n` | US-xx の受け入れ基準 |

### 1.2 優先度

| 優先度 | 意味 |
|---|---|
| Must | 第一フェーズの完了に必須。これがないと公開しない |
| Should | 第一フェーズで実装したいが、スケジュールが厳しい場合は第二フェーズに回してよい |

### 1.3 受け入れ基準の粒度

このドキュメントでは、受け入れ基準を「〜のとき、〜であること」の形で簡潔に書きます。Given / When / Then 形式の詳細な受け入れ基準と、エラー時の挙動・境界値は、`docs/specs/` の機能仕様書で定義します。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 城 | 本サービスで扱う城。第一フェーズでは日本100名城と続日本100名城の計200城（時代を問わない） |
| 武将 | 本サービスで扱う人物。城とのゆかりを登録するため、時代を問わず登録できる。一般向けに掲載するのは、掲載期間に活動した人物のみ |
| 掲載期間 | 一般向けに掲載する武将の活動期間。第一フェーズは織田信長の誕生（1534年）から大坂の陣（1615年）まで。第二フェーズ以降に広げる予定 |
| 非掲載の武将 | 掲載期間外の築城者・城主など、ゆかりを登録するためだけに用意する武将。一般向けの画面には名前だけを表示する |
| 女性 | 武将の母・妻・娘・姉妹など、家族関係を登録するために用意する女性の人物。一覧・検索・詳細画面は持たない。武将として活動した女性は武将として登録する |
| 家族関係 | 武将・女性同士の、親子・養親子・兄弟姉妹・夫婦の関係 |
| ゆかり | 武将と城の関係。城主・居城、築城・改修、生誕地、死没地の4種類 |
| 訪問記録 | 会員が訪問した城について残す記録 |
| 推し武将 | 会員が自分のお気に入りとして登録する武将（1名） |
| 情報提供 | 会員が城・武将の新規データや既存データの修正を提案すること |
| 審査 | 管理者が情報提供の内容を確認し、承認または却下すること |
| 公開プロフィール | 会員の訪問記録などを、第三者が閲覧できるページ |

## 3. 利用者と権限

### 3.1 ロール

| ロール | 説明 |
|---|---|
| 未ログインユーザー | 会員登録していない、またはログインしていない利用者。閲覧のみできる |
| 会員 | 会員登録した利用者。訪問記録、推し武将の登録、情報提供ができる |
| 管理者 | 城・武将データの管理と、情報提供の審査を行う（共同管理者） |
| 特権管理者 | 管理者の権限に加えて、ユーザー管理と管理者アカウントの発行を行う（運営者本人） |

| 公開プロフィールの閲覧 | ○ | ○ | ○ | ○ |
| 訪問記録の登録・編集・削除 | － | △ | △ | △ |

| 情報提供 | － | ○ | ○ | ○ |

## 4. 機能要件

### 4.1 地図

#### US-01 地図で城を探す 【Must】

未ログインユーザー・会員として、日本地図上で城の位置を見たい。なぜなら、旅行先やその周辺にどんな城があるかを知りたいから。

- AC-01-1：トップページを開いたとき、日本全体の地図が表示され、登録済みのすべての城がピンで表示されていること。
- AC-01-2：地図を拡大・縮小・移動できること（スマホではピンチ操作とドラッグ、PCではマウス操作に対応）。
- AC-01-3：ピンが密集して重なる縮尺では、ピンがまとめて表示され、拡大すると個別のピンに分かれること。
- AC-01-4：日本100名城と続日本100名城のピンが、色や形で見分けられること（色だけに頼らない）。
- AC-01-5：ピンを選択したとき、城名・所在地・城郭構造の概要が表示され、詳細画面へ移動できること。
- AC-01-6：地図の上に城の検索ボックスがあり、城名を入力すると候補が表示され、選択するとその城の位置へ移動すること。

#### US-02 地図上で城を絞り込む 【Should】

未ログインユーザー・会員として、地図上に表示する城を条件で絞り込みたい。なぜなら、目的に合った城だけを見たいから。

- AC-02-1：都道府県、城郭構造、100名城／続100名城の区分で、表示するピンを絞り込めること。
- AC-02-2：ログイン中の会員は、「訪問済みのみ」「未訪問のみ」で絞り込めること。

### 4.2 城

#### US-03 城を検索する 【Must】

未ログインユーザー・会員として、城を一覧から検索したい。なぜなら、どこに旅行するかの参考にしたいから。

- AC-03-1：城の一覧画面で、キーワード（城名、別名、所在地）で検索できること。
- AC-03-2：都道府県、旧国名、城郭構造、100名城／続100名城の区分で絞り込めること。
- AC-03-3：100名城番号順、名称順で並べ替えられること。
- AC-03-4：一覧はページ分割して表示されること。
- AC-03-5：検索結果が0件のとき、その旨と条件の見直しを促すメッセージが表示されること。
- AC-03-6：検索条件が URL に反映され、その URL を共有・再訪すると同じ結果が表示されること。

#### US-04 城の詳細を見る 【Must】

未ログインユーザー・会員として、城の詳細情報を見たい。なぜなら、訪問前に城のことを知りたいから。

- AC-04-1：「6.1 城」の項目が表示されること。値が未登録の項目は「不明」または非表示とすること。
- AC-04-2：その城にゆかりのある武将の一覧が、ゆかりの種類（城主・居城、築城・改修、生誕地、死没地）と年代付きで表示され、武将の詳細画面へ移動できること。非掲載の武将は名前だけを表示し、詳細画面へのリンクは表示しないこと。
- AC-04-3：城の位置が小さな地図で表示されること。
- AC-04-4：画像が登録されている場合、画像と出典が表示されること。
- AC-04-5：ログイン中の会員には、訪問記録の登録ボタンと、自分の訪問記録の一覧が表示されること。
- AC-04-6：「この情報の修正を提案する」ボタンから情報提供画面へ移動できること（未ログイン時はログインを促す）。

### 4.3 武将

#### US-05 武将を検索する 【Must】

未ログインユーザー・会員として、戦国武将を検索したい。なぜなら、歴史小説の執筆やゲームの参考にしたいから。

- AC-05-1：武将の一覧画面で、キーワード（氏名、読み仮名、別名・通称、官位）で検索できること。
- AC-05-2：出身（旧国名、現在の都道府県）、所属勢力で絞り込めること。所属勢力は、いずれかの期間で属していれば対象とすること。
- AC-05-3：名前順、生年順で並べ替えられること。
- AC-05-4：一覧はページ分割して表示されること。
- AC-05-5：検索条件が URL に反映されること。
- AC-05-6：一覧と検索結果に、非掲載の武将が表示されないこと。

#### US-06 武将の詳細を見る 【Must】

未ログインユーザー・会員として、武将の詳細情報を見たい。なぜなら、その人物の経歴やゆかりの地を知りたいから。

- AC-06-1：「6.2 武将」の項目が表示されること。
- AC-06-2：家族関係（父親、母親、養父、養母、子、兄弟姉妹、妻・夫）が登録されている場合、一覧で表示されること。家族が掲載武将の場合はその武将の詳細画面へ移動でき、非掲載の武将の場合は名前だけを表示すること。
- AC-06-8：家族が女性の場合、名前と略歴が表示されること（女性の詳細画面はない）。
- AC-06-9：生年と没年が登録されている場合、享年（数え年）が表示されること。
- AC-06-10：官位、所属勢力、主君が、期間付きで年の順に表示されること。主君が掲載武将の場合はその武将の詳細画面へ移動でき、非掲載の武将の場合は名前だけを表示すること。
- AC-06-11：妻が、正室・側室の区分付きで表示されること。
- AC-06-3：ゆかりの城が、ゆかりの種類と年代付きで一覧表示され、城の詳細画面へ移動できること。
- AC-06-4：ゆかりの城の位置が小さな地図で表示されること。
- AC-06-5：生没年が不詳・諸説ありの場合、その旨が表示されること。
- AC-06-6：「この情報の修正を提案する」ボタンから情報提供画面へ移動できること。
- AC-06-7：非掲載の武将の詳細画面にアクセスしたとき、「存在しない」と表示されること。

### 4.4 会員

#### US-07 会員登録する 【Must】

未ログインユーザーとして、会員登録したい。なぜなら、訪問記録や情報提供の機能を使いたいから。

- AC-07-1：メールアドレス＋パスワード、または Google アカウントで登録できること（Better Auth を利用）。
- AC-07-2：メールアドレス＋パスワードで登録した場合、確認メールが送信され、メールアドレスの確認が完了するまで会員機能を使えないこと。
- AC-07-3：登録時に、利用規約とプライバシーポリシーへの同意が必須であること。
- AC-07-4：初回ログイン時に、ユーザー名の入力を求められること（必須）。
- AC-07-5：ユーザー名は他の会員と重複できないこと。

#### US-08 ログイン・ログアウトする 【Must】

会員として、ログイン・ログアウトしたい。

- AC-08-1：メールアドレス＋パスワード、または Google アカウントでログインできること。
- AC-08-2：パスワードを忘れた場合、再設定できること（Better Auth の機能を利用）。
- AC-08-3：ログアウトしたとき、会員専用の画面にアクセスできなくなること。
- AC-08-4：ログインが必要な操作を未ログインで行おうとしたとき、ログイン画面へ誘導され、ログイン後に元の画面へ戻ること。

#### US-09 プロフィールを設定する 【Must】

会員として、自分のプロフィールを設定したい。

- AC-09-1：ユーザー名（必須）、出身都道府県、現在の居住都道府県（いずれも任意）を設定・変更できること。
- AC-09-2：推し武将を1名、登録・変更・解除できること。選べるのは掲載期間の武将（非掲載の武将以外）のみとすること。
- AC-09-3：推し武将がマイページに表示されること。
- AC-09-4：プロフィールの公開・非公開を設定できること（初期値は非公開）。

#### US-10 退会する 【Must】

会員として、退会したい。

- AC-10-1：マイページから退会でき、退会前に確認画面が表示されること。
- AC-10-2：退会したとき、メールアドレス・ユーザー名などの個人情報、訪問記録、アップロードした写真が削除されること。
- AC-10-3：承認済みの情報提供で反映されたデータは削除されず、提供者名は「退会ユーザー」と表示されること。
- AC-10-4：退会したとき、Better Auth のアカウント（認証情報とセッション）も削除されること。

### 4.5 訪問記録

#### US-11 訪問記録を登録する 【Must】

会員として、行った城を記録したい。なぜなら、後から過去にどこへ行ったかを見返したいから。

- AC-11-1：城の詳細画面またはマイページから、訪問記録を登録できること。
- AC-11-2：記録できる項目は、訪問日（必須）、メモ、評価（5段階）、写真（1枚）、御城印の入手有無、100名城スタンプの入手有無であること。
- AC-11-3：同じ城について、訪問ごとに複数の記録を登録できること。
- AC-11-4：訪問日に未来の日付は指定できないこと。
- AC-11-5：自分の訪問記録を編集・削除できること。他人の記録は編集・削除できないこと。

#### US-12 訪問記録を地図と一覧で振り返る 【Must】

会員として、自分の訪問記録を地図と一覧で振り返りたい。

- AC-12-1：ログイン中、地図上で訪問済みの城のピンが、未訪問の城と見分けられること（色だけに頼らない）。
- AC-12-2：マイページで、訪問済みの城数と全城数に対する割合（例：42 / 200城）が表示されること。100名城と続100名城で分けて表示すること。
- AC-12-3：マイページで、訪問記録を訪問日順の一覧で見られること。
- AC-12-4：御城印・100名城スタンプの入手数が表示されること。

#### US-13 公開プロフィールで訪問記録を見せる 【Must】

会員として、訪問記録を他の人に見せたい。なぜなら、自分の城めぐりの実績を自慢したいから。

- AC-13-1：プロフィールを公開に設定している会員には、固有の URL を持つ公開プロフィールページがあること。
- AC-13-2：公開プロフィールには、ユーザー名、推し武将、訪問済みの城の地図、訪問済みの城数、訪問記録（メモ・評価・写真を含む）が表示されること。
- AC-13-3：出身都道府県、現在の居住都道府県は、公開プロフィールに表示するかを会員が個別に選べること。
- AC-13-4：メールアドレスは、いかなる場合も公開プロフィールに表示されないこと。
- AC-13-5：プロフィールが非公開の会員の公開プロフィール URL にアクセスしたとき、「存在しない」と表示され、非公開であることが分からないこと。

### 4.6 情報提供

#### US-14 新しい城・武将の情報を提供する 【Must】

会員として、データにない城や武将の情報を提供したい。なぜなら、その人物や城のことを多くの人に知ってもらいたいから。

- AC-14-1：城または武将を選んで、新規データの情報を入力し、提供できること。
- AC-14-2：出典（参考文献名または URL）の入力が必須であること。
- AC-14-3：承認された場合に提供者名を表示するかどうかを、提供時に選べること。
- AC-14-4：提供した情報は、審査で承認されるまで公開データに反映されないこと。
- AC-14-5：城は、100名城・続100名城以外の城も提供できること。ただし、地図への表示対象とするかは審査で判断する。

#### US-15 既存の城・武将の情報の修正を提案する 【Must】

会員として、既存データの誤りや不足を修正したい。

- AC-15-1：城・武将の詳細画面から、修正したい項目と修正後の値を入力して提案できること。
- AC-15-2：出典の入力が必須であること。
- AC-15-3：提供者名の表示有無を選べること。

#### US-16 自分の情報提供の状況を確認する 【Must】

会員として、自分が提供した情報の審査状況を確認したい。

- AC-16-1：マイページで、自分の情報提供の一覧と状態（審査待ち、承認、却下）を確認できること。
- AC-16-2：却下された場合、却下理由を確認できること。
- AC-16-3：審査待ちの情報提供は取り下げられること。

### 4.7 通知

#### US-17 通知を受け取る 【Must】

会員・管理者として、自分に関係する出来事を通知で知りたい。

- AC-17-1：以下の通知が送られること。

| 通知内容 | 宛先 | システム内通知 | メール |
|---|---|:---:|:---:|
| 会員登録時のメールアドレス確認 | 会員 | － | ○ |
| 情報提供の審査結果（承認・却下） | 提供した会員 | ○ | ○ |
| 運営からのお知らせ | 全会員 | ○ | － |
| 新しい情報提供が届いた | 管理者・特権管理者 | ○ | － |

- AC-17-2：画面上部に未読の通知件数が表示され、通知一覧で既読にできること。
- AC-17-3：審査結果のメール通知は、会員が設定で受け取らないようにできること。

### 4.8 管理機能

管理機能は、一般ユーザー向けの画面とは分けた管理画面で提供する。

#### US-18 城データを管理する 【Must】

管理者として、城の情報を登録・編集・削除したい。なぜなら、ユーザー画面に表示するのに必要だから。

- AC-18-1：城の一覧（検索・絞り込み付き）、登録、編集、削除ができること。
- AC-18-2：緯度経度が日本の範囲外の場合は登録できないこと。
- AC-18-3：削除は論理削除とし、訪問記録が紐づく城を削除しても会員の訪問記録が壊れないこと。
- AC-18-4：誰がいつ変更したかの履歴が残ること。

#### US-19 武将データを管理する 【Must】

管理者として、武将と女性の情報、武将と城のゆかり、家族関係を登録・編集・削除したい。

- AC-19-1：武将の一覧（検索・絞り込み付き）、登録、編集、削除ができること。
- AC-19-2：武将と城のゆかりを、種類と期間付きで登録・編集・削除できること。官位、所属勢力、主君も、期間付きで登録・編集・削除できること。
- AC-19-3：武将・女性同士の家族関係（親子、養親子、兄弟姉妹、夫婦）を登録できること。片方に登録すると、相手側にも反映されること。夫婦には正室・側室の区分を登録できること。
- AC-19-4：削除は論理削除とし、推し武将に設定されている武将を削除しても会員のデータが壊れないこと。
- AC-19-5：誰がいつ変更したかの履歴が残ること。
- AC-19-6：武将ごとに、一般向けに掲載するかどうかを設定できること。
- AC-19-7：女性の一覧（検索付き）、登録、編集、削除ができること。削除は論理削除とし、誰がいつ変更したかの履歴が残ること。

#### US-20 情報提供を審査する 【Must】

管理者として、会員からの情報提供を審査したい。なぜなら、真偽を確認してから公開したいから。

- AC-20-1：審査待ちの情報提供を一覧で確認できること。
- AC-20-2：修正提案の場合、現在の値と提案された値を並べて確認できること。
- AC-20-3：承認すると、内容が公開データに反映されること。承認前に管理者が内容を修正できること。
- AC-20-4：却下する場合、却下理由の入力が必須であること。
- AC-20-5：承認・却下すると、提供者に通知されること（US-17）。

#### US-21 CSV でデータを一括登録・出力する 【Must】

管理者として、城・武将のデータを CSV で一括登録・出力したい。なぜなら、初期データ（城200件、武将100人）を効率よく登録したいから。

- AC-21-1：城、武将、女性、武将と城のゆかり、家族関係、官位・所属勢力・主君の期間について、CSV をアップロードして一括登録・更新できること。
- AC-21-2：登録前に内容の検証が行われ、エラーがある場合は行番号とエラー内容が表示され、1件も登録されないこと。
- AC-21-3：現在のデータを CSV でダウンロードできること。
- AC-21-4：CSV の形式（列の定義）が文書化されていること。

#### US-22 画像を管理する 【Should】

管理者として、城・武将の画像を登録したい。

- AC-22-1：城・武将ごとに画像を1枚登録できること。
- AC-22-2：画像の出典とライセンスの入力が必須であること。
- AC-22-3：画像を差し替え・削除できること。

#### US-23 お知らせを配信する 【Should】

管理者として、全会員にお知らせを配信したい。

- AC-23-1：お知らせを作成し、全会員のシステム内通知に配信できること。

#### US-24 ユーザーを管理する 【Must】

特権管理者として、ユーザーを管理したい。なぜなら、不適切な利用に対応したいから。

- AC-24-1：会員の一覧を検索・閲覧できること。
- AC-24-2：会員を利用停止にできること。利用停止中の会員はログインできず、公開プロフィールも表示されないこと。
- AC-24-3：会員の不適切な訪問記録（メモ・写真）を非表示にできること。

#### US-25 管理者アカウントを発行する 【Must】

特権管理者として、共同管理者を追加したい。

- AC-25-1：既存の会員に、管理者の権限を付与・解除できること。
- AC-25-2：管理者は、他のユーザーの権限を変更できないこと。

#### US-26 官位と所属勢力を管理する 【Must】

管理者として、官位と所属勢力のマスタデータを追加・編集したい。なぜなら、初期データにない官位や勢力が情報提供や調査で見つかったときに、武将・女性に登録できるようにしたいから。

- AC-26-1：官位と所属勢力のそれぞれについて、一覧（検索付き）、追加、編集ができること。
- AC-26-2：項目は、名称（必須）、読み仮名（必須）、コード（必須）であること。
- AC-26-3：コードは他と重複できず、追加後は変更できないこと（URL の検索条件に使うため）。
- AC-26-4：名称を編集したとき、その官位・所属勢力を登録している武将・女性の表示にも反映されること。
- AC-26-5：誰がいつ変更したかの履歴が残ること。
- AC-26-6：削除の機能は第一フェーズでは提供しないこと（武将・女性の登録が壊れないようにするため）。

## 8. 非機能要件

### NFR-01 性能

- 城・武将の一覧画面と詳細画面は、一般的なスマホ回線で2秒以内に主要な内容が表示されること。
- トップページ（地図）は、3秒以内に地図とピンが表示されることを目標とする。
- 測定には Lighthouse などを用い、Core Web Vitals の LCP 2.5秒以内を目安とする。

### NFR-02 対応環境

- PC：Chrome、Safari の最新版
- スマホ：iOS の Safari、Android の Chrome の最新版
- スマホでの利用を優先したレスポンシブデザインとする（画面幅 360px 以上で崩れないこと）。

### NFR-03 可用性

- 個人開発のため、数時間の停止は許容する。
- メンテナンスで停止する場合は、可能な範囲で事前にお知らせする。

### NFR-04 バックアップ

- データベースは1日1回自動でバックアップし、7日分を保持する。
- アップロードされた画像も、データベースと同じ期間で復元できること。
- 第一フェーズの公開前に、バックアップから実際に復元できることを1回以上確認する。

### NFR-05 セキュリティ

- すべての通信を HTTPS で行う。
- OWASP Top 10 の代表的な脆弱性（SQL インジェクション、XSS、CSRF、アクセス制御の不備など）への対策を行う。
- 権限のチェックはバックエンドで必ず行う。
- 入力値はフロントエンドとバックエンドの両方で検証する。
- アップロードできる画像は JPEG・PNG・WebP、1枚5MB以下とする。
- 会員がアップロードした写真からは、位置情報などの Exif 情報を削除してから保存する。
- 秘密情報（API キー、DB 接続情報など）はリポジトリに含めず、環境変数などで管理する。
- 依存パッケージの脆弱性を定期的に確認する（GitHub の Dependabot などを利用）。

### NFR-06 個人情報・法令

- 公開前に、利用規約とプライバシーポリシーを作成し、サイト上で公開する。
- プライバシーポリシーには、取得する情報、利用目的、外部サービス（Google ログイン、メール送信サービスなど）への提供について記載する。
- 退会時の個人情報の扱いは US-10 に従う。

### NFR-07 アクセシビリティ

- WCAG 2.2 レベル AA を目標とする。
- すべての操作をキーボードで行えること。
- 文字と背景のコントラスト比を確保すること。
- 画像には代替テキストを付けること。
- 情報を色だけで区別しないこと（地図のピンを含む）。
- 地図を操作できない利用者でも、城一覧・検索から同じ情報にたどり着けること。

### NFR-08 対応言語

- 日本語のみとする。

### NFR-09 規模

| 項目 | 想定（初年度） |
|---|---|
| 登録会員数 | 100人程度 |
| 城 | 200件 |
| 武将 | 100人程度 |

この規模で性能要件を満たすこと。利用者が増えた場合は、インフラを段階的に拡張する（`constitution.md` 7.2）。

### NFR-10 費用

- インフラと外部サービスの費用は、月額1,000円以内を目標、3,000円を上限とする（`constitution.md` 7.3）。

### NFR-11 運用・監視

- アプリケーションのエラーを記録し、重大なエラーに気づける仕組みを用意する。
- 本番環境へのデプロイは CI/CD で自動化し、手作業を最小限にする。

### NFR-12 テスト

- ドメインロジックには Unit テストを書く。
- 主要なユーザーの流れ（US-01、US-03、US-11、US-14、US-20）には E2E テストを書く。
- テストは CI で自動実行し、失敗した場合はマージしない。
