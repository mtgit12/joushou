## 1. このドキュメントの読み方

### 1.1 ファイルの分け方

機能仕様書は、次のルールで1ファイルにまとめます。

- 同じ画面や同じデータを扱い、一緒に実装・テストするユーザーストーリーは1ファイルにまとめる（例：城の検索と詳細）。
- 優先度が異なるユーザーストーリーは分ける。Should をまとめて第二フェーズに回せるようにするため。
- 一般向けの機能と管理画面の機能は分ける。権限と画面が異なるため。
- 1ファイルが大きくなりすぎないようにする。AI エージェントに1ファイル単位で渡しやすくするため（憲章 8.4）。

### 1.2 番号とファイル名

- テンプレートは _template.md を使う。
- ファイル名は `NNN-<機能名>.md` とし、`NNN` は3桁の連番とする。
- 番号は機能の分類ごとに並べており、実装の順番を表すものではない（実装の順番は `tasks.md` で定める）。
- 一度割り当てた番号は変更・再利用しない。機能を追加する場合は末尾の番号を使う。

### 1.3 列の意味

| 列 | 意味 |
|---|---|
| 作成済み | 仕様書を作成したら `☐` を `☑` に書き換える |
| 優先度 | `requirements.md` 1.2 の Must / Should |
| 対象ロール | その機能を利用するロール（`requirements.md` 3.1）。詳細な権限は `requirements.md` 3.2 を参照 |

## 4. 機能仕様書で扱わないもの

複数の機能にまたがる内容は、機能仕様書ではなく次のドキュメントで定義し、各機能仕様書から参照します。

| 内容 | 定義するドキュメント |
|---|---|
| ログイン方式、セッション、ロールと権限の詳細 | `docs/design/auth.md` |
| 画面一覧、画面遷移、管理画面のダッシュボード | `docs/design/screens.md` |
| テーブル定義、マスタデータ（都道府県、旧国名、元号、城郭構造）、年の表現（不詳・諸説あり・〜頃） | `docs/design/data-model.md` |
| エラーコードとユーザー向けメッセージ | `docs/design/errors.md` |
| エンドポイント、リクエスト／レスポンス | `docs/api/openapi.yaml` |
| 利用規約、プライバシーポリシー | `docs/legal/terms.md`、`docs/legal/privacy-policy.md` |
